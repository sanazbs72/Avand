# Interface Contracts — V02

This contract specializes [Financial Operations F04](../../../docs/FINANCIAL_OPERATIONS.md#f04-buygold) for the approved [V02 spec](../spec.md). Principal rounds down to a whole rial, limits apply to the final pre-fee principal and normal-mode purchases require full backing. Preserve the existing [V01 contract](../../001-fund-irr-wallet/contracts/v01.md).

## Customer surface

Resolve customer identity from authenticated credentials. A body ID or retry key never grants authority. Reject malformed or unauthorized requests before admission and use the same not-found response for a missing or foreign reference. Customer reads do not trigger financial work.

| Interface | Request and response |
| --- | --- |
| `POST /api/v1/gold/buy-quotes` | Accept positive whole `requestedPrincipalIrr`. Return 201 with quote ID, buy price per gram, quoted weight in mg, final principal IRR, fee rate and amount, total debit IRR, UTC issue/expiry and the advisory maximum in mg when available. Invalid amount or order bounds returns a customer-safe validation reason. If current price or required quote inputs are unavailable, return a retryable unavailability reason. A known wallet or backing shortfall can be shown separately from quote terms. Issuance claims no funds or capacity. |
| `POST /api/v1/gold/buy-orders` | Accept only `quoteId` and a customer-scoped `Idempotency-Key` header. Confirm the exact stored terms. Return 202 with order ID and status location after durable admission. Exact retry returns the same acknowledgement, including after expiry. Same key with another quote returns 409. A different key for an already claimed quote returns 409 without a second order. |
| `GET /api/v1/gold/buy-orders/{orderId}` | Return the owned order, exact authorized amounts, status `Processing`, `FinancialOutcomeUnknown`, `Completed` or `Rejected`, and a safe reason when applicable. Expired rejection includes a refresh action and the original requested principal. Obtain a new quote from the quote endpoint and display it for explicit confirmation with a new key. |
| `GET /api/v1/gold/balances` | Return committed `availableIrr` and `availableGoldMg` for the authenticated customer. Report retryable unavailable if Ledger cannot supply the result. Zero represents an authoritative empty balance. |

The quote observation uses buy ask from a paired positive ask and bid with a valid provider UTC observation time. Use the source timestamp at issuance, never the transport arrival timestamp. The advisory maximum is the minimum of backing headroom, fee-inclusive affordable mg and order cap in mg, using the same exact arithmetic as posting. If the maximum cannot satisfy the configured minimum, report no currently available quantity. A 202 is an admission receipt. Financial success is visible from the stored Ledger decision applied to the order.

## Application → Ledger

Use a distinct authenticated `Application.Trading` credential for BuyGold, its own operation inquiry and delegated trade balance/financial-state reads. Payments retains F02, V01 controls and the existing balance response. Register each shared internal route once and dispatch by authenticated producer and permitted type. An ordinary customer or synthetic feed client has no Ledger credential.

| Interface | Request and response |
| --- | --- |
| `POST /internal/v1/operations` | Common versioned envelope with `operationType=BuyGold`, stable operation ID, envelope customer ID and business reference `GoldOrder` / order ID / `Execute`. Payload holds one strict nested `quoteSnapshot` with side Buy, quote ID, UTC issue/expiry, ask IRR/g, mg, final principal IRR, fee rate ppm, fee IRR, total debit IRR and quote policy version. The authenticated issuer attests the immutable mapping from requested amount to weight. The Ledger independently checks exact economics and binds the quote claim to issuer and customer. |
| `GET /internal/v1/operations/{operationId}` | Return the stored result under producer scope. Posted includes operation and business references, journal reference, protected decision time and typed `incrementalUncoveredGoldMg` of zero or more. Rejected includes protected decision time, stable safe reason and no new journal. Replay returns the same result and procurement increment. Current balances are read separately. |
| `GET /internal/v1/customers/{customerId}/financial-state` | Trading-scoped read of committed customer IRR/gold balances, effective eligibility and shared backing headroom or unavailable status for advisory use. No customer-visible disclosure of other customers' claims or raw inventory. |

Ledger computes the first decision against the effective limits, spendable wallet, backing and eligibility. It accepts only a supported quote policy with the originally quoted fee. Check that the issue time is not in the future, the lifetime is exactly 30 seconds and protected decision time is strictly before expiry. Use existing 200 Posted/Rejected and 409 payload-conflict semantics. Use explicit reasons for expired quote, eligibility, order bounds, insufficient funds, exceeded backing and unavailable evidence. A previously stored identical result takes precedence over current guards. An ordinary 404 on inquiry or a timeout leaves outcome unknown. Recovery retries with the same identity and frozen request. Application applies a definitive result and any positive procurement intent without contacting the custodian.
